# 双机换网验证 · 2026-11-22

两台独立的 Ubuntu ARM64 虚拟机分别运行控制端 `engineer` 和被控端 `device`。从 `938ecf9` 上的本地工作区构建 Linux ARM64 程序，两台机器分别核对了程序的 SHA-256。

```text
ee9df55f4e6e65461c298b1815fc1eeb3d8381e9dd78f57e4f8aec70724b0086
```

## 同一授权内先后切换两端网络

每轮只交换一次邀请和回执，打开两个独立的 SSH shell。切换时移除旧地址、关闭 `eth0`，从 `roam0` 经新网关接入另一子网。新私网之间没有直达路由，网关只给本端已经使用的 UDP 端口建立映射。测试核对了网关上的 UDP 地址转换计数。

| 换网的一端 | 地址变化 | 第一轮 | 第二轮 | 第三轮 |
| --- | --- | ---: | ---: | ---: |
| 被控端 | `10.77.2.2 → 10.78.2.2`，新出口 `198.18.1.2` | 10.8 秒 | 11.2 秒 | 11.1 秒 |
| 控制端 | `10.77.1.2 → 10.78.1.2`，新出口 `198.18.1.1` | 9.5 秒 | 8.6 秒 | 9.6 秒 |

时间从开始接入新网络算到该端的检查全部完成，包含 SSH 登录、读取主机名和网卡地址，以及核对两端授权和网关计数。每轮被控端换网后，两个原窗口的远端 shell PID 均与换网前一致。控制端断网 26 秒后再换网，原终端断开，`peertty link` 仍以 `ptlab` 登录 `lima-device`。

三轮中两端后台的监听端口和签名凭证的 SHA-256 在换网前后均相同，`peertty status` 均报告换网直连。每轮最后由被控端撤销，两端都释放了授权，后续 SSH 登录被拒绝。[复现命令和网络拓扑](../lab/README.md#验证换网后沿用原授权)

最终构建改为分批轮询多网卡设备的全部已签名候选地址。两台虚拟机再次核对程序的 SHA-256 为 `e1ec8e1661b33c705ee2609f7308e3c9a6bd522a64fd02fc9ca8a0186c0e2200`。被控端换网后 10.9 秒、控制端换网后 8.9 秒分别完成上述检查。被控端原窗口的两个 shell PID 保持一致，控制端能沿用原授权重新登录，被控端随后成功撤销。

## 首次连接之前换网，等待授权自然到期

两端交换邀请、回执并完成核验。被控端随后断网，在本机批准这份 180 秒的授权。保持离线超过 60 秒后，被控端通过新网关接入 `10.78.2.2`。控制端用原回执首次登录，在两个独立的 SSH 窗口执行命令，另一次 SSH 登录读到了新网卡地址。

两个窗口一直开到签名授权到期，随后都断开。两端均释放了授权，新登录被拒绝，两个窗口此前完成的写入仍能在被控端读回。已有系统 SSH 服务的进程号前后相同。

## 双 NAT 与 UDP 受限场景回归

最终构建在同两台虚拟机运行了 `./lab/ctl punch-check` 的六种场景。延迟 40 秒交付回执并使用备用 STUN、NAT 重映射源端口、弱网下两种角色分配均通过真实 SSH 登录。四轮的两端都选择了经 NAT 映射的 UDP 候选地址。

当两个网关为 STUN 和对端分配不同外部端口时，双方都获取了映射，但无法建立直连。完全封锁 UDP 时，双方均未获取映射。这两种情况下都没有建立 SSH 会话，被控端 22 端口始终关闭。

## 本地检查

macOS 上 `go test -race -count=1 ./...` 和 `go vet ./...` 全部通过。测试覆盖了错误回执、篡改或重放的报文、从错误地址或套接字返回的应答，以及撤销后尝试启用新路径。另用不声明换网能力的对端分别发起邀请和回执，两种组合均能通过普通 ICE 建立数据通道。Windows amd64 已完成交叉构建。真实 Wi-Fi 与蜂窝网络之间的切换仍待实测。
