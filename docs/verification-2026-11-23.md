# PeerTTY 第三身份接入审查 · 2026-11-23

## 双虚拟机身份验证

两台独立的 Ubuntu ARM64 虚拟机在弱网双 NAT 下交换签名邀请和回执。先批准一个控制端并打开两个 SSH shell，再在控制端虚拟机的独立配置目录生成另一套设备密钥。第三身份与获批方使用相同主机名和目标账号，通过正式菜单回答同一份邀请。两份回执的发行公钥不同，会话编号、邀请摘要和接收方相同。

| 场景 | 第三身份 | 已授权身份 |
| --- | --- | --- |
| `engineer → device`，已有系统 SSH | 被控端拒绝更换回执。`link` 返回 1，终端数为 0 | 以 `ptlab` 登录 `lima-device`，两个 shell 的 PID 在检查前后均为 64583、64656 |
| `device → engineer`，按授权临时启动 SSH | 替换回执被拒绝。`link` 返回 1，终端数为 0。批处理 SFTP 也被拒绝 | 以 `chiway` 登录 `lima-engineer`，两个 shell 的 PID 保持 66819、66879，SFTP 的 `pwd` 返回该账号的主目录 |

两轮都通过 `udp srflx/srflx` 建立直连，被控端信任记录中都只有获批公钥。主动撤销后，两个原终端均关闭，新登录被拒绝，终端已完成的两条写入均可读回。第一轮已有 SSH 服务保持 PID 1984，第二轮撤销后 22 端口没有监听或已建立连接。

两端均核对了同一个 Linux ARM64 测试程序的 SHA-256。程序从随后提交为 `e578702` 的修复源码构建，使用 Go 1.27.4。[复现双机测试](../lab/README.md#检查同名第三身份)

## 双端换网回归

用干净的 `e578702` 重新构建，双机核对 SHA-256 为 `7a6ace293ed3943be79fcbdeca600baa412c1dce184fd524e096461ba4d837f9`。被控端换网后，原先两个 shell 均保留 PID。控制端断网 26 秒再换网后，沿用原授权重新登录成功。两端从接入新网到完成登录、地址及授权核对分别用时 10.7 秒和 9.5 秒。

随后被控端撤销授权，双方后台均退出，新终端被拒绝。两台虚拟机最终均处于启动状态，实验网络已恢复为原来的 `extreme nat`。[复现换网回归](../lab/README.md#验证换网后沿用原授权)

## 安全判断

本次检查覆盖第三方持有邀请、知道主机名和目标账号，但只持有自己设备密钥的情况。已建立的授权只接纳获批控制端。首次配对时，持有邀请的人都能生成自己的有效回执。被控方应通过可信渠道核对工程师的设备指纹，再批准相应回执。已批准私钥泄露和终端操作系统失陷均超出本次实验范围。
